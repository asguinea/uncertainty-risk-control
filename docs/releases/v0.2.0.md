# v0.2.0 — risk-controlled social media analysis

Release date: **10 September 2026**. [GitHub release](https://github.com/asguinea/risk-controlled-social-media-analysis/releases/tag/v0.2.0). This version adds HumAID and TweetEval Sentiment while preserving the earlier GoEmotions evidence and immutable v0.1.0 release.

## What changes

The repository is named **risk-controlled-social-media-analysis**, with a domain-focused description covering emotion tagging, sentiment classification and crisis triage. The Python distribution remains `uncertainty-risk-control`, import `uncertainty_risk_control`, and CLI `uqrc`; package metadata advances to 0.2.0.

HumAID adds source/target crisis-post deprioritization, calibration-label requirements, event slices and a carefully separated transfer comparison. TweetEval Sentiment adds four risk budgets, class selection, warm-up summaries and source/TEST interpretation. The three-study navigation, research note and original figures explain the common research question while retaining each task's action, reference and population.

## Findings and limits retained

Strict GoEmotions budgets leave most comments for review. HumAID source-to-target transfer and target-local locked results have different roles and denominators, so their difference is not a paired causal recalibration result. The source full-pool milestone at 4,774 labels is one warm-up run. TweetEval retains the 2.5% final review-all outcome, sparse neutral selection at 5%, and 15.1884% observed selected error at a 15% budget.

Each budget uses delta 0.05 under the stated assumptions, without joint study/budget/class/event assurance or automatic protection under distribution shift. Human labels define the references. Final-calibration replay and aggregate regeneration do not reproduce historical training, inference, all warm-up prefixes, or source-to-assignment construction.

Included assets are original code, projected sufficient statistics, aggregate records, analytical figures and documentation. Source posts, row-level identities/labels/scores, keys, weights, tokenizers and product runtime remain excluded. [License scope](../../LICENSE_SCOPE.md) and [third-party notices](../../THIRD_PARTY_NOTICES.md) retain the HumAID humanitarian-research terms and unresolved acquisition-metadata limits. This release does not relicense upstream data.

## Downloads and verification

The package filenames are `uncertainty_risk_control-0.2.0-py3-none-any.whl` and `uncertainty_risk_control-0.2.0.tar.gz`. The wheel contains the method, CLI, all study replay/report modules and hash resources. The source archive additionally contains evidence, tests, examples, plotting scripts, figures and documentation. It supports the [complete reproduction guide](../reproduction.md).

The [installed verification script](../../scripts/verify_reproduction.py) builds both artifacts, inspects their contents, installs the wheel into a fresh environment outside the checkout, executes 68 unit tests and 150,000 synthetic trials, regenerates all three reports, and compares all figure numerical/provenance inputs exactly except environment metadata. Matplotlib stays optional. Publication-boundary and complete-history secret scans supplement manual review.

The release also provides `verification-v0.2.0.json` and `SHA256SUMS`. The verification record identifies the exact commit/tree, source-file hashes, artifact hashes, local checks and Linux/macOS/Windows CI results. Checksums bind the source archive, wheel and verification record. These repeated synthetic runs test platform consistency, not independent benchmark replication.

Use the source archive or the `v0.2.0` Git tag for the [documented reproduction commands](../reproduction.md). The Python distribution, import and CLI names are unchanged. The wheel alone does not include the evidence files and figure workflow.

GitHub release signatures and SHA-256 hashes identify the published bytes. They do not independently authenticate original predictions or validate the statistical assumptions. Cross-platform image bytes and wheel archive hashes need not match; scientific source bytes, replay decisions, report text and figure numerical inputs are checked separately.
